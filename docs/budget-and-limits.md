# 每日预算与停止条件

依据《项目书》第 15 节：

> 费用来自模型账号、Cloudflare 与 Actions。上线前按实际账号核对额度，
> 设置任务次数、执行时间、返修次数、CI 次数和账单预算；
> **成本统计不可仅依赖 agent 自报。**

> 第 11 节：**每日预算和停止条件** `<DAILY_BUDGET_AND_LIMITS>` 为必填项。

本文件由 **B 端（OpenCode）** 拟定初稿，数值为**可调建议值**，需双方确认生效。

---

## 0. 重要前提

这些数值是**停止闸门（circuit breaker）**，不是费用预测。
目的是让系统在异常时**尽快停下来找人**，而不是继续消耗。

> **成本统计不得仅依赖 agent 自报**（第 15 节）。
> 执行器上报的用量只作参考，最终以模型服务商和 Cloudflare/Actions 的**账单数据**为准。

---

## 1. 三层预算结构

| 层级 | 作用 | 触发后的动作 |
| --- | --- | --- |
| L1 单任务上限 | 防止单任务失控 | 超时即终止，计入返修 |
| L2 每日软上限 | 提醒并降速 | 告警，停止派发**新**任务，在途任务跑完 |
| L3 每日硬上限 | 强制停止 | 停止领取，全部转 `blocked_quota` |

**核心原则**：软上限"跑完在途任务"，硬上限"立刻停领"。
不要在软上限处强制杀死在途任务，否则会产生大量半成品提交。

---

## 2. 具体阈值

### 2.1 任务次数（每日）

| 项目 | 建议值 | 依据 |
| --- | --- | --- |
| 规划任务 | 5 | 需求通常一天不会超过几个 |
| 实现任务 | 20 | 双端并行，每台每任务 30 分钟，理论上限约 32 |
| 诊断任务 | 5 | 第 9 节：归因不明先诊断，不默认归咎最后提交者 |
| 返修任务 | 10 | 单任务最多返修 2 次，按 20 个实现任务估算 |
| **任务总数软上限** | **30** | 达到即告警 |
| **任务总数硬上限** | **40** | 达到即停领 |

### 2.2 执行时间（每日）

| 项目 | 建议值 | 依据 |
| --- | --- | --- |
| 单任务超时 | 30 分钟 | 第 7 节默认值 |
| 单台每日执行时长 | 6 小时 | 双机约 12 机时/天 |
| **每日总机时软上限** | **10 机时** | 告警 |
| **每日总机时硬上限** | **14 机时** | 停领 |

### 2.3 返修次数

| 项目 | 建议值 | 依据 |
| --- | --- | --- |
| 单任务返修上限 | **2** | 第 7 节默认值 |
| 同一任务累计尝试上限 | 3 | 首次 + 2 次返修 |
| 达到上限后 | 转 `needs_input` | 第 13 节：停止消耗并提出具体待决问题 |

> **验收 V13**：重试上限到达后必须停止消耗并提出**具体**待决问题，
> 而不是笼统地说"失败了"。

### 2.4 CI 次数（每日）

| 项目 | 建议值 | 依据 |
| --- | --- | --- |
| 整合批次 | 10 | 第 7 节：同项目一次仅整合一个批次 |
| Actions 运行次数 | 15 | 含组合测试与重跑 |
| **CI 分钟软上限** | **300 分钟** | 告警（私有仓库 Actions 计费） |
| **CI 分钟硬上限** | **500 分钟** | 停领 |

### 2.5 账单预算（每日）

| 项目 | 建议值 | 说明 |
| --- | --- | --- |
| 模型账号 | **$5 / 天** | 按各自订阅实价核对，不是估算 |
| Cloudflare | **$1 / 天** | Workers + Durable Object 用量 |
| GitHub Actions | **$2 / 天** | 私有仓库超量计费 |
| **合计软上限** | **$8 / 天** | 告警 |
| **合计硬上限** | **$12 / 天** | 停领 |

> 上述金额为**初始保守值**，首周实测后按真实账单调整。
> 第 15 节要求"按实际账号核对额度"，因此必须用真实账单替换这里的推测。

## 3. 停止条件（触发即动作）

### 3.1 立即停止领取（硬）

| 触发条件 | 动作 | 对应状态 |
| --- | --- | --- |
| 达到任何硬上限 | 停止领取新任务 | `blocked_quota` |
| 模型配额耗尽 | 停止对应执行器的任务 | `blocked_quota` |
| 登录失效 | 停止该执行器 | `blocked_auth` |
| 同一任务返修超限 | 该任务转待决 | `needs_input` |
| 同一错误 1 小时内连续 5 次 | 停止该执行器 | `needs_input` |
| CI 连续 3 个批次失败 | 停止自动整合 | `needs_input` |
| 检测到敏感文件试图提交 | 立即阻断 | `blocked_approval` |
| main 分支出现并发写入 | **关闭自动合并** | `blocked_approval` |

### 3.2 告警但继续（软）

| 触发条件 | 动作 |
| --- | --- |
| 达到软上限 | 告警，停止派发**新**任务，在途任务跑完 |
| 单任务超过 20 分钟 | 记录，监控是否接近超时 |
| 租约连续 2 次失效 | 记录，检查网络与心跳 |
| 返修率 > 50% | 告警，怀疑契约或规划质量问题 |

## 4. 必须分类而非重试的情形

第 8 节明确：**登录过期与配额不足分别标记，不按代码失败反复返修**。

| 情形 | 错误码 | 处置 | 是否重试 |
| --- | --- | --- | --- |
| 登录过期 | `AUTH_EXPIRED` | `blocked_auth` | ❌ 否 |
| 配额耗尽 | `QUOTA_EXHAUSTED` | `blocked_quota` | ❌ 否 |
| 限流 | `RATE_LIMITED` | `retryable` | ✅ 退避后重试 |
| 代码失败 | `TESTS_FAILED` 等 | `repairable` | ✅ 计入返修 |

> **禁止无限重试**（验收 V10）。

## 5. 计费口径

| 项目 | 计费方 | 核对方式 |
| --- | --- | --- |
| 模型用量 | 各自模型服务商 | 服务商账单页 |
| Workers / DO 请求 | Cloudflare | Cloudflare 控制台 |
| Actions 分钟 | GitHub | GitHub Billing 页 |

统计与停止判定挂在 **Cloudflare Durable Object**（第 7 节），
因为它已经是任务与状态的权威来源。

### 成本统计纪律

- ❌ 不得仅依赖 agent 自报用量
- ✅ 以云服务账单为准
- ✅ 摘要标明来源任务和版本（第 11 节）
- ✅ 每日汇总落库，供后续调整阈值
